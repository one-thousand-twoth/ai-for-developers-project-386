# Domain Docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.
If these do not exist, proceed silently. Domain-modeling creates
them when terms or decisions are resolved.

## Layout

Single-context: one root `GLOSSARY.md` and `docs/adr/`.
Use sequentially numbered ADR filenames.

## Vocabulary and decisions

Use the glossary's terms in issues, proposals, hypotheses, and tests.
Reconsider unfamiliar synonyms; record real vocabulary gaps for domain-modeling.
Explicitly flag proposals that contradict an existing ADR.
